# Analisi UX — Rilocazione

**Stato:** PRONTA PER L'ANALISI
**Priorità:** ALTA
**Ordine:** 4
**Confronto:** MyAstral.org / Astrolab
**Ambito:** workflow completo della rilocazione astrologica.

---

## 1. Obiettivo

Valutare se l'astrologo può selezionare una località, generare il tema rilocato, comprenderne gli effetti e confrontarlo con altre località senza perdere il soggetto corrente.

---

## 2. Prerequisiti

1. Leggere `START_HERE_ux.md`.
2. Leggere `00_METODOLOGIA_ux.md`.
3. Verificare `DECISION_LOG_ux.md` e `BACKLOG_ux.md`.
4. Utilizzare lo stesso soggetto di prova nelle due applicazioni.
5. Preparare almeno tre località di prova: vicina, nazionale e internazionale.

---

## 3. Evidenze richieste

Creare e utilizzare:
- `evidence/myastral/rilocazione/`
- `evidence/astrolab/rilocazione/`

Screenshot minimi:
1. accesso alla rilocazione;
2. selezione del soggetto;
3. ricerca della località;
4. risultati della ricerca geografica;
5. tema rilocato;
6. dati e cuspidi;
7. cambio località;
8. confronto tra rilocazioni;
9. stampa o esportazione;
10. errori o assenza di località.

---

## 4. Step A — Accesso alla funzione

1. Selezionare il soggetto.
2. Individuare la funzione Rilocazione.
3. Contare clic e schermate necessarie.
4. Verificare se il soggetto corrente viene mantenuto.
5. Verificare quali dati sono precompilati.
6. Acquisire lo screenshot iniziale.

---

## 5. Step B — Ricerca della località

1. Cercare una località conosciuta.
2. Verificare suggerimenti e completamento automatico.
3. Controllare come vengono distinte località omonime.
4. Verificare nazione, regione, coordinate e fuso orario.
5. Selezionare la località.
6. Cambiare località prima del calcolo.

| Aspetto | MyAstral.org | Astrolab | Note |
|---|---|---|---|
| Suggerimenti | | | |
| Località omonime | | | |
| Coordinate visibili | | | |
| Fuso orario | | | |

---

## 6. Step C — Generazione della rilocazione

1. Avviare il calcolo.
2. Contare i clic.
3. Verificare feedback e stato di avanzamento.
4. Controllare se soggetto e località restano visibili.
5. Verificare il titolo del risultato.
6. Acquisire lo screenshot completo.

---

## 7. Step D — Lettura del risultato

Verificare la presenza e la gerarchia di:
- grafico astrologico;
- Ascendente e Medio Cielo;
- cuspidi;
- posizioni planetarie;
- aspetti;
- differenze rispetto al tema natale;
- dati geografici;
- data e ora;
- azioni disponibili.

Valutare se l'astrologo comprende immediatamente cosa è cambiato.

---

## 8. Step E — Cambio località

1. Tornare alla selezione della località.
2. Scegliere la seconda località.
3. Verificare quali dati vengono conservati.
4. Generare la nuova rilocazione.
5. Ripetere con la terza località.
6. Controllare se il passaggio richiede operazioni ripetitive evitabili.

---

## 9. Step F — Confronto tra rilocazioni

1. Verificare se più rilocazioni possono essere salvate.
2. Verificare se esiste un confronto diretto.
3. Confrontare almeno due località.
4. Controllare chiarezza, allineamento e contesto.
5. Verificare eventuali limiti.

| Azione | Visibile | Clic | Contesto mantenuto | Note |
|---|---:|---:|---:|---|
| Salvare rilocazione | | | | |
| Aprire confronto | | | | |
| Cambiare una località | | | | |

---

## 10. Step G — Stampa ed esportazione

1. Individuare stampa ed esportazione.
2. Verificare quali dati vengono inclusi.
3. Controllare soggetto, località e titolo.
4. Verificare leggibilità e ordine.
5. Controllare se è necessario ricostruire il contesto.

---

## 11. Step H — Errori e casi limite

Verificare:
- località non trovata;
- località omonima;
- input incompleto;
- coordinate anomale;
- cambio di località dopo il risultato;
- ritorno alla schermata precedente;
- conservazione dei dati inseriti;
- messaggi di errore comprensibili.

---

## 12. Step I — Ripetizione in Astrolab

Ripetere integralmente gli Step A-H in Astrolab usando lo stesso soggetto e le stesse località.

Le differenze di calcolo vanno annotate separatamente: il confronto corrente riguarda il workflow.

## 15. Decisioni

Registrare:
- punti di forza di Astrolab da preservare;
- criticità riproducibili;
- passaggi duplicati;
- termini poco naturali;
- proposte nel `BACKLOG_ux.md`;
- decisioni nel `DECISION_LOG_ux.md`.

Non trasformare differenze funzionali in problemi UX senza evidenze.
